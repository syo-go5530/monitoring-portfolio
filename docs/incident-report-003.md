# 障害報告書 #003：ディスク空き容量の逼迫（2段階検知）

## サマリー
監視対象領域のディスク空き容量が段階的に減少し、リソース監視により検知。
第1段階で LowDiskSpace（warning）、第2段階で CriticalDiskSpace（critical）が
設計どおり順に発報し、ファイル削除により回復した。
本件は監視基盤の動作検証を目的とした計画的な障害試験である。

## 基本情報
| 項目 | 内容 |
|---|---|
| インシデントID | INC-003 |
| 発生日 | 2026-08-24 |
| 重要度 | Warning → Critical（段階的に上昇） |
| 検知方法 | Prometheus リソース監視（Node Exporter） |
| 発報アラート | LowDiskSpace / CriticalDiskSpace |
| ステータス | 復旧済み |

## 監視値の推移
| タイミング | 空き容量 | 空き率 | 発報アラート |
|---|---|---|---|
| 平常時 | 100 MB | 100% | なし |
| 第1段階（85MB使用） | 15 MB | 15% | LowDiskSpace（warning） |
| 第2段階（92MB使用） | 8 MB | 8% | LowDiskSpace + CriticalDiskSpace |
| 回復後 | 100 MB | 100% | なし |

## タイムライン
| 時刻 | 出来事 |
|---|---|
| （9:20） | 監視領域に85MBを書き込み、空きが15%に低下（障害発生） |
| （9:25） | 空き20%未満が5分継続し、LowDiskSpace が FIRING に遷移（warning発報） |
| （9:35） | 追加で7MBを書き込み、空きが8%に低下（事態悪化） |
| （9:36） | 空き10%未満が1分継続し、CriticalDiskSpace が FIRING に遷移（critical発報） |
| （9:40） | 書き込んだファイルを削除、空きが100%に回復（復旧） |
| （9:41） | 両アラートが Inactive へ戻る |

## 影響
- 影響範囲：監視対象のディスク領域
- 影響内容：ディスク空き容量の逼迫。満杯に至った場合、書き込み不能によりサービスが即時停止する恐れがある
- 継続時間：約（合計の分数）分

## 根本原因
監視対象領域への継続的なファイル書き込みにより、空き容量が段階的に減少した。
（今回は検証目的で、隔離した試験用領域に対し意図的に dd コマンドでファイルを作成した）

## 対応内容
1. Prometheus の Alerts 画面で LowDiskSpace（warning）の発報を確認
2. 事態の悪化に伴い CriticalDiskSpace（critical）の発報を確認
3. 書き込んだファイルを削除し、空き容量を解放
4. 空き容量の回復および両アラートの解消を確認

## 検知が機能した点（良かった点）
- 2段階のアラート設計が意図どおりに機能し、warning → critical の順で発報した
- 空き15%の時点では warning のみが発報し、critical は発報しなかった。閾値による段階分けが正しく機能している
- critical の for を1分と短く設定したことで、危機的状況をより速く検知できた（warning の for は5分）

## 考察：2段階設計の有効性
ディスクは他のリソースと異なり、満杯でサービスが即時停止し、かつ自然回復しない性質を持つ。
本試験により、以下の2段階設計が実際に機能することを確認できた。
- 第1段階（20%未満・warning）：対処の準備を促す予兆検知
- 第2段階（10%未満・critical）：即時対応を求める危機検知
段階を分けることで、「まだ猶予がある状態」と「即時対応が必要な状態」を区別して通知でき、
対応の優先順位付けが可能になる。単一閾値では、この区別ができない。

## 安全に配慮した試験設計（工夫した点）
本番のルートディスクを直接逼迫させると、システム全体に影響が及ぶ。
そのため、node-exporter に容量制限付きの隔離領域（tmpfs, 100MB）を用意し、
アラートルールの監視対象を一時的にその領域へ向けて試験を実施した。
これにより、実環境に一切影響を与えずにディスク逼迫を再現・検証できた。
試験後はアラートルールを本来のルートディスク監視に戻している。

## 再発防止・改善案
- ディスク使用量の増加傾向を Grafana でダッシュボード化し、逼迫の予兆を早期に把握する
- 不要ファイルの自動削除（ログローテーション等）の仕組みを導入し、逼迫そのものを予防する
- 今後の改善：ディスク使用量の増加ペースから満杯までの時間を予測する監視の追加を検討する
